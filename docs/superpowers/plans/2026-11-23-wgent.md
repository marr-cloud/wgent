# wgent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `wgent`, a single Go binary that lets humans and AI agents list, start, stop and inspect WireGuard tunnels on Windows without UAC prompts, with JSON output and an optional tray icon.

**Architecture:** One executable with two roles. A Windows service (`wgent service run`, LocalSystem) listens on the named pipe `\\.\pipe\wgent` and performs privileged work by driving the Service Control Manager, `wireguard.exe /installtunnelservice|/uninstalltunnelservice` and `wg.exe show <n> dump`. Every other subcommand is an unprivileged client that talks to the service over the pipe. Pure logic (config, name resolution, dump parsing, health verdict, request handling, CLI output) lives behind interfaces and is unit-tested with fakes; Windows-only adapters are thin.

**Tech Stack:** Go 1.25+ (toolchain 1.27), `golang.org/x/sys/windows` (`svc`, `svc/mgr`, `registry`), `github.com/Microsoft/go-winio` (named pipes), `github.com/BurntSushi/toml`, `fyne.io/systray`, stdlib `flag`. GoReleaser + GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-23-wgent-design.md`

## Global Constraints

- Module path `github.com/marr-cloud/wgent`; binary `wgent.exe`; main package `cmd/wgent`.
- `go.mod` declares `go 1.25`. Windows-only code uses `_windows.go` suffix; pure packages must build and test on any OS.
- All user-facing text (CLI messages, errors, README) in **English**.
- Tunnel names must match `^[A-Za-z0-9_=+.-]{1,32}$`.
- WireGuard paths: `C:\Program Files\WireGuard\wireguard.exe`, `C:\Program Files\WireGuard\wg.exe`, configs in `C:\Program Files\WireGuard\Data\Configurations\` (`<n>.conf.dpapi` preferred over `<n>.conf`). Derive `Program Files` from `%ProgramFiles%`.
- Tunnel service name: `WireGuardTunnel$<name>`. wgent service name: `wgent`, display name `wgent (WireGuard for agents)`.
- Pipe path `\\.\pipe\wgent`; SDDL `D:P(A;;GA;;;SY)(A;;GA;;;BA)(A;;0x12019b;;;<installer SID>)` (read/write without FILE_CREATE_PIPE_INSTANCE; final-review fix I1). Dial verifies the pipe server PID equals the SCM-reported PID of service `wgent`, whose account must be LocalSystem.
- Service installs itself to `%ProgramFiles%\wgent\wgent.exe`.
- `ProtocolVersion = 1`.
- Health threshold: handshake age < 180 s → `up`; otherwise `degraded`.
- up/down wait timeout: 15 s, polling every 250 ms.
- Config file: `$XDG_CONFIG_HOME/wgent/config.toml` if `XDG_CONFIG_HOME` is set, else `%USERPROFILE%\.config\wgent\config.toml`. Keys: `default_tunnel` (string), `[tray] poll_seconds` (int, default 2).
- Exit codes: 0 OK, 1 generic, 2 usage / no default tunnel, 3 wgent service not installed or unreachable, 4 tunnel not found, 5 timeout.
- Error codes (JSON `error.code`): `usage`, `no_default_tunnel`, `invalid_tunnel_name`, `service_not_installed`, `protocol_mismatch`, `tunnel_not_found`, `timeout`, `internal`.
- The service never accepts file paths or arbitrary commands; only `list`, `status`, `up`, `down` with a validated tunnel name that exists in the configurations directory.
- TDD for every task with logic; commit after each task. Commit messages: conventional commits, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Service exists but is Stopped/StartPending** (e.g. a user ran `Stop-Service`, or the WireGuard GUI left it) → `up` must start the existing service, not reinstall; `status` must say `down` for Stopped and keep waiting through StartPending. Pinned in Task 5 (`TestUpStartsExistingStoppedService`) and Task 3 (`TestVerdictPending`).
2. **Tunnel running but peer never handshook** (`latest-handshake` = 0) → `degraded` with a reason, never `up`. Pinned in Task 3 (`TestVerdictNeverHandshook`).
3. **Name with path characters** (`..\evil`, `a/b`, `C:\x.conf`, 33 chars) → rejected with `invalid_tunnel_name` both in the client and again in the service. Pinned in Task 2 (`TestValidateName`) and Task 5 (`TestHandlerRejectsInvalidName`).
4. **Config file missing or malformed** → missing means "no default" (not an error); malformed TOML is an error naming the file path. Pinned in Task 1 (`TestLoadMissingFile`, `TestLoadMalformed`).
5. **wgent service not installed / pipe absent** → client reports `service_not_installed` with hint `sudo wgent service install`, exit 3, in both human and `--json` modes. Pinned in Task 7 (`TestServiceNotInstalledJSON`).

    - missing/stopped → `down`, `""`

    - running + newest handshake age < threshold → `up`, `""`
    - running + newest handshake never → `degraded`, `"no handshake with any peer yet"`
    - running + newest age ≥ threshold → `degraded`, `"last handshake <N>s ago; peer may be unreachable (or idle without PersistentKeepalive)"`
